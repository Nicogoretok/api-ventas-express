API de Ventas

Referencia para consultar ventas y registrar nuevas operaciones. Todas las respuestas se envían en formato JSON.

Inicio rápido

En desarrollo, el servidor escucha en el puerto 3000 de forma predeterminada. Si se configura la variable de entorno PORT, se utiliza ese puerto.

URL base:

http://localhost:3000/api/v1/ventas

La API no configura autenticación. Para consumirla desde otro entorno, reemplaza localhost:3000 por el host y puerto donde esté desplegado.

Endpoints

GET/consolidado

Obtiene el consolidado de ventas de una sucursal para un año. Ambos parámetros son obligatorios.

ParámetroUbicaciónRequeridoDescripción
sucursalQuerySíSucursal a consultar; el valor aceptado depende de los datos de la base de datos.
anioQuerySíAño para el consolidado.
 
curl "http://localhost:3000/api/v1/ventas/consolidado?sucursal=1&anio=2025"

Respuesta 200 OK:

{
  "status": "success",
  "total_registros": 1,
  "data": [
    { "...": "Las columnas dependen del procedimiento almacenado" }
  ]
}

Si falta algún parámetro, responde 400 Bad Request con {"error":"Bad Request","message":"Debe Enviar Ambos Parametros"}.

GET/:id

Busca una venta por su identificador.

ParámetroUbicaciónRequeridoDescripción
idRutaSíIdentificador numérico de la venta.
 
curl http://localhost:3000/api/v1/ventas/123

Respuesta 200 OK:

{
  "status": "success",
  "data": { "...": "Columnas de la venta devuelta por la base de datos" }
}

400 Bad Request si el ID no es numérico; 404 Not Found si no existe una venta con ese ID.

POST/consolidado

Registra una venta. Envía un objeto JSON con todos los campos indicados.

CampoTipo esperadoRequeridoDescripción
id_productoNúmeroSíIdentificador del producto.
id_clienteNúmeroSíIdentificador del cliente.
cantidadNúmeroSíCantidad vendida.
fecha_ventaCadenaSíFecha de la venta. Se recomienda formato YYYY-MM-DD.
 
curl -X POST http://localhost:3000/api/v1/ventas/consolidado \
  -H "Content-Type: application/json" \
  -d '{
    "id_producto": 10,
    "id_cliente": 25,
    "cantidad": 2,
    "fecha_venta": "2025-03-08"
  }'

Respuesta 201 Created:

{
  "status": "success",
  "message": "Venta registrada exitosamente",
  "datos_registrados": {
    "id_producto": 10,
    "id_cliente": 25,
    "cantidad": 2,
    "fecha_venta": "2025-03-08"
  }
}

Si falta uno o más campos, responde 400 Bad Request. Un error de base de datos responde 500 Internal Server Error.

Formato y errores

  • Para solicitudes POST, usa Content-Type: application/json.
  • Los errores se devuelven como JSON con las propiedades error y message.
  • Los valores posibles de sucursal, las columnas de salida y las restricciones de los datos dependen de la base de datos y de sus procedimientos almacenados.
  • La API no publica un endpoint de salud ni una especificación OpenAPI.

La documentación refleja los campos y códigos de respuesta definidos por el servidor. Verifica con el responsable de la base de datos los valores válidos y la estructura exacta de los resultados.
